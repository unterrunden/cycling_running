# cycling_running: coaching toolkit

This README is the index of the toolkit. It is synced into the Project and read in every chat; the code itself is only opened when it is used.

The repo is public and the sandbox can clone it. Claude cannot push to GitHub: new or changed files are handed over in the chat and Pat commits them.

## Start of a chat that needs analysis (the sandbox resets every chat, sometimes mid-chat)
```sh
git clone --depth 1 https://github.com/unterrunden/cycling_running repo && cd repo
pip install fitparse scipy pandas --break-system-packages -q
python3 selfcheck.py        # 73 checks (about 2 min): every PASS = the toolkit still reproduces the validated numbers
```

## Cookbook (task → command; `import cp_lib as cp, routes_tool as rt`)
- First look at any FIT: `cp.fit_inspect(f)`. Lap-button blocks, pauses, strap: `cp.fit_laps(f)`, `cp.fit_pauses(f)`, `cp.fit_events(f)`, `cp.hrv_quality(f)`; a new max HR against clean beats: `cp.hr_peak_clean(f)`.
- W' for intervals.icu (which uses the activity FTP as CP): `cp.wprime_needed(P, 175)` per hard ride, `cp.wbal(P, 175, 18000)` for the curve, `cp.pd_fit(bests)` / `pd_fit(bests, model='morton')` for CP models; 12 Nov choice 18 kJ (coach_notes.md section 3).
- Ride report: `python3 analysis_tools.py f.fit` (FTP from `cp_lib.CFG`; `--ftp N` overrides); session view (blocks, best windows with HR and speed, decoupling, efforts): `cp.ride_session(f)`.
- Long outdoor ride (v3, everything of the 21 / 22 Nov analyses): `python3 analysis_tools.py f.fit --report --carbs 160 --fluid 1350`; in Python `at.long_ride_report(f)` (dict).
- Plan a ride on a route: `python3 analysis_tools.py --plan route.gpx --power 120 --start 11:00 --date 2026-11-29 --wind 14 --wind-from 120` (moving time, clock times per 10 km, sunset, climbs, cut options); refill places on the route: `rt.near_places(f, {name: (lat, lon)})` (coordinates from a map search); new roads vs the routes zip: `rt.route_overlap(f, glob.glob('gpx/*.gpx'))`; recalibrate the time model after a long ride: `rt.calibrate_time(ride_fit, avg_w, moving_s)`.
- 4DP / Full Frontal: `cp.fourdp_report(f)` (sprints with a physics check, per-minute blocks, gaps with stopped time, strap quality, FTP by the 4DP rule).
- Window / block detail: `a, ex, tl = cp.load_activity(f)`; `cp.best_window(tl, 1200, 'elapsed')`; `cp.ride_blocks(tl, 10)`.
- Run trial: `cp.run_finish_report(f)`; reps: `rs = cp.run_series(f)`; `cp.fastest_windows(rs, 240, 3)`; `cp.split_table(rs, 500)`.
- Routes: `python3 routes_tool.py DIR`; `--compare A B`; `--diag F`; `--entry F C28`; in Python `rt.analyse(f, merge_km=0.35)`, `rt.stretches(r)`, `rt.moderate_bends(f)`, `rt.loop_closure(f)`.
- Wind and distance: `cp.distance_table(powers=(180, 185, 190), winds=(-10, 0, 10))`; `cp.implied_headwind(174, 27.2, 0.0056)`; `cp.cp_fit([(300, 231), (1200, 184)])`.
- Daylight: `cp.sun_times(datetime.date(2026, 11, 29))`.
- Digest refresh (v2, from 20 Nov): add the new chat FITs to `tests/` and their rows to `data/session_context.csv` (RPE, feel, fan, room temperature, strap ranges), update `data/strava_bests.json` from the connector, then `python3 digest_tool.py --export strava_export_<dd_mm>.zip --out docs/history_digest.md --asof YYYY-MM-DD` (new export activities are appended to the context automatically; check them and rerun; `--no-sync` leaves the context untouched, `--tables DIR` writes the output tables elsewhere). The 1 Hz sessions are cached in `.cache/` (ignored by git via `.gitignore`). About monthly add `--calibrate` (HCI context model and reference). Session metrics by hand: `x = cp.session_1hz(f, 'vride')`, `cp.ride_load(x, cp.ftp_for(day))`, `cp.aero_decoupling(x, 'ride', 175)`, `cp.efficiency_factor(x, 'ride')`, `cp.hrr_events(x, 'ride', 175)`.
- Digest v1 (until 19 Nov; kept for the selfcheck): `python3 analysis_tools.py --batch EXPORT/activities --csv EXPORT/activities.csv --out digest --ftp 180` (the batch dir is the export's `activities` folder), then `cp.make_history_digest('digest/digest_rides.csv', 'digest/digest_runs.csv', 'history_digest.md', strava_now=cp.parse_bests('5s=686@2026-11-01, ...'), strava_virtual=cp.parse_bests('5s=413@2026-11-06, ...'), ftp=180, asof='...', export_name='Strava export of ...', hr_notes={'2026-10-17': '(HR unusable, Pat)'}, run_notes='...', after_archive_md=[...])`. Ride and VirtualRide bests come from the connector (`get_athlete_best_efforts`); outdoor and indoor rides are kept apart; a Strava best newer than the export shows in bold, and `extra_monthly` adds it to the monthly table. New bests go into the tables, not into extra text.
- Segments: `python3 segments_tool.py` (newest export + tests/*.fit → `segments_archive.csv` + markdown); new segment: `acts = st.load_rides(); st.fingerprint(acts, km=1.56, time_s=221, w=248, cad=88, hr=183, hrmax=189)`, then `st.add_segment(...)`, `st.save_segments(data)` (`import segments_tool as st`).
- 60-min FTP test (or any long test): `cp.hour_test_report(edge_fit, other=kickr_fit)` (best window, 5-min blocks, halves, decoupling, LTHR estimate = HR of the last 20 min, KICKR vs Stages on the same window).
- HR quality and zones: `cp.hr_artefact_scan(tl)` (minute ranges where HR cannot match the power: 200 W / 45 s and 150 W / 2 min tiers), `cp.hr_gaps(tl)` (missing HR while riding; Strava draws it as a frozen line); `w = cp.hr_power_windows(tl)` per ride, stacked → `cp.hr_zone_score(w, [133, 148, 162, 173], ftp)` / `cp.hr_zone_optimise(w, ftp)`.
- Progress checks (coach_notes.md section 7): aerobic check `cp.aerobic_check(kickr_fit, other=edge_fit)` (20 min at 130 W + 10 min at 150 W: HR of the last 10 / 5 min, drift, W/HR, meter ratio; v1.14: the earliest near-target block, the Edge HR as `other_hr_last`); long-ride durability `cp.ride_session(f)` (decoupling); run pace and HR per lap `cp.split_table(cp.run_series(f), 1265)`.
- Running threshold HR and HR zones (17 Nov): `r = cp.run_1hz(f, bad=[(from_min, to_min)])` (1 Hz series; blank frozen strap values), `w = cp.run_hr_pace_windows(r)` (steady 3-min windows, HR of the last minute), `m = cp.run_hr_pace_model({name: w, ...}, exclude=(...))` (bpm per km/h + day offsets; `m['hr_at'](300)` = HR at 5:00/km), `cp.run_hr_zone_score(W, [150, 164, 173, 188], [386, 333, 299, 280])` / `cp.run_hr_zone_optimise(W, pace_edges)` (HR zones vs Strava or `cp.friel_run_pace_edges(tp)` pace zones), `cp.friel_run_hr_zones(lthr)`, `cp.vdot(5000, 1410)` / `cp.vdot_pace(v, minutes)` / `cp.riegel_time(...)`, `cp.run_tt_report(f)` (time trial or 5K: HR of the last 20 min = Friel's LTHR estimate).
- KICKR vs Stages with MyWhoosh timer freezes (v1.17, the default for tests): `r = cp.meter_compare(edge_fit, mywhoosh_fit, windows=[(start_s, end_s)])` (monotone lag path `cp.align_monotone`; band table, matched-window averages, `r['jumps']` = the freezes). Power-duration forecasts: `cp.pd_predict(seconds)` (2P at `CFG['cp']` / `CFG['wprime']`, 3-20 min) and `cp.pd_power_law(600, p10, 3600, p60)` (whole 3-60 min range).
- Two power meters at once (KICKR vs Stages): `cp.meter_offset(cp.fit_series(edge_fit), cp.fit_series(kickr_fit), align="power")` (v1.6: align by power for MyWhoosh files, whose HR runs about 4 s late; `mask=[(from_epoch, to_epoch)]` drops broken stretches; default align by HR as before; compare blocks by their averages, the band table is biased next to ERG targets; power-band table, linear fit; v1.12: `res["erg"]` = same-window averages of every ERG hold, `res["warn"]` flags piecewise offsets from MyWhoosh timer freezes and an unconfirmed weak alignment, `res["notes"]` length differences; per-segment lags: `cp.segment_lags(ref, other)`); a stream instead of a FIT: `cp.stream_series(streams, '2026-11-06T15:51:40')`.
- Edit markdown safely: `p = cp.Patch('coach_notes.md'); p.rep(old, new, 'tag'); p.insert_after('- [stated] ...', new); p.save('out.md')` (refuses to save if any target is missing). Attached or exported Project docs first through `cp.normalize_md(src, dst)` (CRLF, space-only blank lines, headings).

## Conventions
- Elapsed-based = Strava power-curve convention (stopped or paused seconds count as 0 W); rolling / moving = stopped seconds removed, coasting kept (Strava average-power convention).
- FTP settings in Strava and intervals.icu: 170 W (since 1 Nov); 4DP result 183-184 W; planning FTP 175 W since the 60-min trainer test of 12 Nov (`CFG['ftp']`). Load metrics use the FTP of the month (`cp.FTP_MONTH`: Aug-Oct 170, Nov 175). 4DP Full Frontal: FTP = 100% of the 20-min average. Model and zone defaults live in `cp_lib.CFG`.
- Local time Europe/Berlin; `activities.csv` timestamps are UTC.
- Power scales: outdoor = Stages (left-only), indoor = KICKR. Settled after five dual-recorded rides (6-14 Nov): the KICKR reads about +2 to +6 W (+2-5%) in Z2, the same within about 2% from tempo to 600 W at normal cadence (hour test 12 Nov: ratio 1.002), and about +8% below 60 rpm (7 Nov). Planning FTP 175 W on both scales; indoor Z2 targets about 5 W above the outdoor ones.

## Gotchas (details in `SCRIPT_CATALOGUE.md`)
- Strava-made run FIT files: use the distance field, not speed. Garmin ride FITs have gaps where the timer paused. GPX run distance can over-read; trust Strava's best efforts for runs.
- The HR-flag counter in `analysis_tools.py` is capped at 8 and uninformative for rides: use `cp.hr_plateaus` / `cp.hrv_quality`.
- Turn counts depend on the definition: 100 m windows, 55°; C1 (4dp v2) has 28 unmerged, 17 with a merge radius of 350 m.
- komoot GPX has no surface, crossing or traffic-light data; komoot elevation is noisy (ascent ±10%, occasional spikes: see `rt.elevation_diag`).
- Trainer rides are a separate Strava sport (VirtualRide) with their own best efforts; trainer HR without a strong fan is inflated.
- HR lags 30-90 s: genuine 45-s efforts at 200+ W can average 128-142 bpm; judge strap artefacts by the HR at the end of an effort (or falling HR), not by the average.
- The Strava connector returns the run/default HR zones (<130/160/175/190), not the cycling set kept in the app.
- MyWhoosh start times can be off (51 s on 6 Nov): align by cross-correlation (`cp.meter_offset`; by power since 11 Nov: MyWhoosh's Bluetooth HR runs about 4 s behind the Edge's ANT+ HR). Edge 540 HRV messages hold some junk RR values (6-58 s), now ignored. An Edge recording indoors with GPS on draws a scribble and uploads a 0.1 km outdoor "Ride" to Strava: use an indoor profile and delete the duplicate.
- MyWhoosh freezes its timer when the app is in the background for more than about 10-15 s and drops the frozen time from its file (14 Nov: 4.0 min shorter than the Edge file, offsets growing piecewise): one whole-ride lag is then wrong. `meter_offset` warns (v1.12); use `cp.segment_lags` or the ERG-hold averages (`res["erg"]`), and the Edge file as the duration reference.
- MyWhoosh FITs carry virtual GPS (sub_sport `virtual_activity`), the Edge indoors records `indoor_cycling`: outdoor tools (segments) skip both.
- Strava segment power with an auto-paused stop inside the effort counts the stop as 0 W (= the elapsed-based value; 31 Oct, 67 s stop: 147 vs 157 W over recorded samples).
- A best-effort curve can rise with duration (4 Nov: 10 min 177 W > 8 min 176 W): harder stretches at both ends of the window, not an error.
- The sandbox shell is `sh`: no `time` builtin, no process substitution (use `bash -c` or temp files).

## `cp_lib.py` function index (generated by `python3 cp_lib.py --index-md`)

### CONFIG
- `fmt_t`: Seconds -> m:ss text (e.g. 1410 -> 23:30).

### PHYSICS
- `power_needed`: Pedal power (W) needed for ground speed v_kmh on a grade (fraction); wind_kmh > 0 = headwind.
- `speed_from_power`: Ground speed (km/h) for pedal power P (W).
- `implied_headwind`: Headwind (km/h, negative = tailwind) that the model needs to explain speed v_kmh at power P.
- `effort_distance`: Distance (km) covered in `minutes` at constant power P: how long a corner-free stretch must be.
- `distance_table`: Table of effort distance by power (rows) and wind (columns, + = headwind km/h).
- `cp_fit`: Two-parameter critical-power sketch from [(seconds, watts), ...] (>= 2 points; least squares of work vs time).
- `cp_predict`: Power (W) the critical-power sketch predicts for an effort of `seconds` (CP + W'/t).
- `pd_predict`: Predicted all-out power (W) for `seconds` from the working 2P model (CFG cp / wprime, v1.17).
- `pd_power_law`: Power law P(t) = p1 * (t / t1) ** k through two best efforts (t in s).

### SUN
- `sun_times`: (sunrise, sunset) as 'HH:MM' local time for date d (NOAA approximation, DST-aware).

### PATCH
- `Patch`: Safe edits of a text file.
- `normalize_md`: Clean a Project doc exported or attached from claude.ai (CRLF line ends, blank lines holding a space, headings glued to the line above): LF line ends, trailing spaces removed, whitespace-only lines emptied, a blank line before every heading outside code fences, one final newline.
- `doc_token_check`: Safety net for a doc rewrite (v1.16, from the 21 Nov coach-notes restructure): every number token (e.g. 175.1, 16:38, 3:41, 21059503183) and every [Pat ...] / [Strava ...] / [mine ...] tag of the old text that no longer appears in the new one.

### FIT
- `fit_inspect`: First look at a FIT file: producer/device, sport, session summary, record channels and counts, time span, gaps, timer events, laps, HRV.
- `fit_laps`: Lap table (lap button / auto laps): start (local), elapsed, timer, distance, power, HR, cadence, ascent, work, trigger.
- `fit_events`: Timer events (start / stop_all with trigger auto|manual), markers, off-course notices.
- `fit_pauses`: Timer pauses: from each stop_all to the next start: offset into the file, duration, and what triggered the stop (auto / manual).
- `hrv_quality`: Beat-to-beat (RR) quality from the FIT 'hrv' messages (Garmin ride files; Strava-made files have none).
- `hr_peak_clean`: Peak HR from artefact-free beats (FIT 'hrv' messages): checks a new max HR against the strap's own 1-s values.

### LOADING (uses `analysis_tools.py`)
- `load_activity`: Load a GPX / FIT / FIT.GZ activity.

### RIDE
- `ride_blocks`: Table of consecutive blocks of MOVING time (stops removed): avg W, NP, HR avg/max, pedalling cadence.
- `best_window`: Best mean-power window of dur_s seconds.
- `decoupling`: Aerobic decoupling over a power / HR series (same length, e.g. moving seconds): efficiency factor (NP/HR) of the 1st vs 2nd half.
- `hr_by_power`: Mean HR and seconds per power band (default bands: <100, 100-135, 136-155, 156-180, >180 W).
- `find_efforts`: Find hard efforts in a power series (1 Hz): start when 5-s mean >= start_w (default 1.2 x FTP), continue while >= hold_w (default 0.97 x FTP), keep those >= min_len s.
- `ride_session`: One-call post-ride summary of a ride file: totals, 10-min blocks, best windows (elapsed + moving) with HR/speed, decoupling, HR by power, efforts.

### RUN
- `run_series`: Distance-based series of a run: dict with t (s), dist (m, recorded distance if the file has it), mt (moving-time axis, pauses removed), hr, lat, lon.
- `split_table`: Splits every `step` metres (moving time): from_m, to_m, time_s, pace_s_km, hr_avg, hr_max.
- `halves`: First vs second part of a run (default: half distance): times, paces and how much faster the second part was (%, positive = negative split).
- `tail_paces`: Time and pace over the last L metres of a run, for each L.
- `fastest_windows`: Fastest non-overlapping windows of window_s seconds (for interval runs / reps): start (moving min), pace, distance, HR avg/max.
- `hr_plateaus`: Runs of >= min_len identical consecutive HR readings (possible held values / strap trouble) and the count of NaN seconds.
- `hr_steps`: Sudden HR steps (mean of the next `win` s vs the previous `win` s differs by >= thr bpm, at most one per minute).
- `hr_zone_time`: Share of valid HR seconds per zone.
- `loop_length`: Length (m) of the first lap of a loop course: first return within `tol` m of the start after min_m metres (None if none).
- `run_finish_report`: One-call summary for a trial / race run: km splits with HR, 500 m splits, halves, tail paces, HR zone shares, HR plateaus, loop length.

### RUN ZONES
- `run_1hz`: GPX / FIT run -> 1 Hz dict for HR-zone and threshold work: T (s), D (m; FIT: the recorded distance field, GPX: positions), V (m/s, 30-s centred), H (bpm; NaN where not recorded or blanked by `bad` = [(from_min, to_min)] on the elapsed clock, e.g. frozen strap values), E, rec (recorded second), stop (inside a gap or a standstill of >= stop_s s), cont (s of continuous running since the start or the last stop: HR kinetics), n.
- `run_hr_pace_windows`: Quasi-steady windows of one run (r = run_1hz() dict, or a path) for HR-zone and threshold work: every `step_s` a `win_s` window without stops whose 30-s speeds vary by at most `max_cv` (CV) and which ends at least `min_cont_s` into continuous running; HR = mean of its last `hr_last_s` s (HR lags 30-90 s).
- `run_hr_pace_model`: HR (last minute of each window) = slope x speed (km/h) + one offset per run, fitted on {run_name: run_hr_pace_windows array} (runs in `exclude` left out, e.g. a hot day).
- `friel_run_pace_edges`: Friel's run pace zones collapsed to 5 (Z5 = 5a-5c) for a threshold pace `tp` (s/km; Friel: the average pace of a solo 30-min time trial): slowest-first edges Z1|Z2|Z3|Z4|Z5 = 129%, 113.5%, 105.5%, 99.5% of tp (TrainingPeaks 'Quick guide').
- `friel_run_hr_zones`: Friel's run HR zones (% of LTHR: Z1 <85, Z2 85-89, Z3 90-94, Z4 95-99, Z5a 100-102, Z5b 103-106, Z5c >106) in bpm.
- `run_hr_zone_score`: How well 5 HR zones (upper edges, e.g. [150, 164, 173, 188]: Z1 < 150 ...; Pat's set from 17 Nov) reproduce the pace zone (slowest-first pace edges in s/km, e.g. friel_run_pace_edges(286) or Strava's auto zones [386, 333, 299, 280]) of each window (run_hr_pace_windows rows).
- `run_hr_zone_optimise`: Grid search of the Z2/Z3, Z3/Z4 and Z4/Z5 run HR edges (Z1 edge fixed: hardly any windows slower than recovery pace) that maximise run_hr_zone_score's balanced accuracy; also the range of each edge over all sets within `tol` of the best (how well the data pin it down).
- `vdot`: Daniels-Gilbert VDOT of a race performance.
- `vdot_pace`: Pace (s/km) for a VDOT: the all-out pace for an effort of `minutes` (Daniels-Gilbert %VO2max-duration curve) or the pace at a fraction `frac` of VO2max (Daniels' threshold pace is about 0.88).
- `riegel_time`: Riegel prediction t2 = t1 (d2/d1)^k.
- `run_tt_report`: Hard continuous run (time trial, 5K race, Friel's 30-min test): distance, time, pace, VDOT, HR average, HR of the last `last_s` s (Friel's LTHR estimate when the effort is a solo 30-min TT; a 5K reads 1-2 bpm higher), HR at the 10-min mark, per-km pace and HR, HR drift (bpm/min, speed-adjusted, from the steady windows).

### TESTS
- `top_windows`: Best `n` non-overlapping mean-power windows of `dur_s` seconds in p[lo:hi] (at least `sep_s` apart).
- `sprint_energy_check`: Plausibility check of a sprint's power (seconds s..e of the timeline): meter energy vs the physics needed for the measured acceleration plus drag.
- `fit_series`: FIT -> dict(t=epoch seconds, p, hr, cad) of the record messages, for meter_offset().
- `stream_series`: Strava connector streams (dict with time, watts, heart_rate; any resolution) + the activity's start_local ('2026-11-06T15:51:40') -> dict(t=epoch seconds, p, hr).
- `segment_lags`: Lag of `other` against `ref` (both fit_series()/stream_series() dicts, same ride) per segment of `seg_s` seconds of the OTHER file, found by power cross-correlation within +-max_lag s.
- `erg_blocks`: Stretches where `other` holds a constant power (ERG target: every second within +-hold_w W of the stretch median for at least min_s s), with the average of both meters over the same seconds (first and last edge_s s left out).
- `meter_offset`: Compare two power meters recorded at the same time (e.g. ref = Edge/Stages FIT, other = KICKR via MyWhoosh FIT or stream).
- `hr_artefact_scan`: Minute ranges where HR cannot match the power (strap artefacts).
- `hr_gaps`: Stretches of riding (power or speed present) with missing or zero HR (strap lost) of at least min_s seconds (short gaps inside a stretch end it): [(from_min, to_min)].
- `hr_power_windows`: Quasi-steady windows of one ride for HR-zone work: every 60 s a `win_s` window (after the first `skip_s`), moving throughout, 10-s power CV <= max_cv; HR = mean of its last `hr_last_s` s (HR lag).
- `hr_zone_score`: How well 5 HR zones (upper edges, e.g. [133, 148, 162, 173]: Z1 < 133 ...) reproduce the power zone (Coggan 5-zone fractions of ftp) of each window.
- `hr_zone_optimise`: Grid search of the Z2/Z3, Z3/Z4 and Z4/Z5 HR edges (Z1 edge fixed: few steady recovery windows) maximising hr_zone_score's balanced accuracy.

### METERS (v1.17)
- `align_monotone`: Lag path that maps a second recording onto a reference: other index = ref index - lag.
- `meter_compare`: KICKR (other, e.g. the MyWhoosh FIT) against Stages (ref, the Edge FIT) on matched seconds, robust to MyWhoosh timer freezes (align_monotone).
- `hour_test_report`: Analyse a long all-out test (default the 60-min FTP test) from one FIT (e.g. Edge/Stages), optionally a second recording of the same ride (`other`, e.g. the MyWhoosh/KICKR FIT): best `dur` window (elapsed: pauses count as 0 W), per-block W / HR / cadence, halves, pacing CV of 1-min means, Pw:HR decoupling, HR drift, LTHR estimate = average HR of the last `lthr_last_s` seconds (Friel), NP; with `other`: its average over the same (aligned; align="power" by default since v1.6, see meter_offset) window and the meter_offset table.
- `aerobic_check`: Aerobic check (progress check for goal a, every second week): 20 min at 130 W, then 10 min at 150 W, inside the Z2 part of a ride (KICKR, fan, usual room).
- `fourdp_report`: Analyse a 4DP / Full Frontal file (two 5-s sprints, 5 min, 20 min, 1 min, in that order) without laps or manual input.

### W' / CP
- `wbal`: W' balance (J) per second of a 1 Hz power series.
- `wprime_needed`: Smallest W' (J) that keeps W'bal >= 0 over a power series, for both W'bal models: dict(integral, at_s, tau, differential).
- `pd_fit`: Power-duration model fit to best efforts {seconds: watts}.

### METRICS
- `ftp_for`: FTP used for load metrics on a date 'YYYY-MM-DD' (FTP_MONTH, else CFG['ftp']).
- `roll`: Trailing w-sample mean (NaN for the first w-1 samples); NaN inputs count as 0.
- `norm_power`: Normalized Power: 4th-power mean of the 30-s rolling mean (Coggan).
- `session_1hz`: 1 Hz session dict from a FIT/GPX/TCX file.
- `stream_run_1hz`: 1 Hz run session from a reduced Strava stream (time s, distance m, HR): linear interpolation; gaps > gap_s = stopped; HR before min_d metres or below min_hr = invalid (strap not yet working).
- `clean_hr`: HR with strap artefacts blanked: manual minute ranges [(from, to)], hr_artefact_scan hits (+-1 min, rides) and 1-2 s jumps of more than jump_bpm (+-10 s).
- `ride_load`: Ride load over the moving samples: sec, km, avg_w, np_w, IF, TSS (sec x NP x IF / (FTP x 3600) x 100), VI, easy / tempo / thr+ shares (% of moving time at <= 77%, 77-90%, > 90% FTP; coasting counts as easy) and mean cadence (pedalling only).
- `run_load`: Run load: sec, km, pace and normalised pace (s/km; 30-s speed, 4th-power mean, no grade adjustment), IF = normalised speed / threshold speed, rTSS = h x IF^2 x 100 (threshold pace RUN_THR_PACE).
- `hr_stats`: Moving HR: mean, max and highest 30-s mean (needs >= 50% valid samples).
- `aero_decoupling`: Aerobic decoupling (%): efficiency (ride NP / HR, run speed / HR) of the first half over the second half, minus 1, on the moving part without the start (ride 10 min, run 5) and the end (ride 5 min, run 2); halves by moving time.
- `efficiency_factor`: EF: ride NP / mean HR (W per bpm); run mean speed in m/min / mean HR.
- `hrr_events`: 1-min HR recoveries [(t_end, hr_peak, drop, 'mod'|'max')].
- `pmc`: Performance-management chart from {date: TSS}: CTL (42-d) and ATL (7-d) exponential averages, TSB = yesterday's CTL - ATL (form going into the day).
- `lowpass`: First-order lag (time constant tau s); NaN counts as 0.
- `lowpass2`: Asymmetric lag: rises with t_on, falls with t_off (HR comes up faster than it settles).
- `hr_intensity`: Model input I: power / FTP (rides) or speed / threshold speed (runs), clipped to 0..1.3, 0 while stopped.
- `hr_features`: (fast, slow) model features: lowpass2(I; t_on, t_off) and lowpass(I; t_slow).
- `hr_model_fit`: Pooled within-session fit of HR = b_s + k1 fast + k2 slow + d t_min over the usable samples (s['ok']) of sessions with >= min_s of them.
- `hr_model_sessions`: Fit the HR model to [(key, kind, x, H_clean, ftp)] of one sport and blank strap dropouts with it (second cleaning pass: HR more than neg_thr below the model (+-30 s) or more than pos_thr above it (+-10 s)).
- `hci_context`: Expected HR offset (bpm) from the factors of one session, relative to the reference (18 C, outdoors or new fan, feel 5, ATL 35, RPE as expected for its IF and duration).
- `hci_zone_credit`: Share of samples whose HR zone equals the zone of the predicted HR (adjacent zone = half credit).
- `hci_badness`: Composite badness: 0.45 |level| + 0.35 dynamics + 0.20 zone mismatch, each divided by its median over the reference sessions (1 = typical).
- `hci_percentile`: Goodness percentile of a badness value against the sorted reference badness values (mid-rank plotting positions, linear in between; beyond the reference range it moves linearly towards 100 at badness 0 or 0 at 1.5 x the worst).
- `scale_score`: Pat's 0-100 scale from a goodness percentile (median 75, P10 55, P90 88, P97.5 93; HCI_ANCHORS).
- `value_percentile`: Goodness percentile of a raw value (EF, HRR, |decoupling|) within reference values (mid-rank, linear in between, clamped 0-100).
- `lookup_rows`: Value at every `step`-th goodness percentile (5..95) of a metric, for the digest's score lookup table.
